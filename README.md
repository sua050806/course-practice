## 1. 서비스 소개

### 대상 사용자

수강신청을 앞둔 대학생

### 해결하려는 문제

수강신청은 정해진 시각에 모두가 동시에 신청해서, 인기 과목은 몇 초 만에 마감된다.
실제 수강신청은 학기에 한 번뿐이라 미리 연습해 볼 방법이 없다.

이 서비스는 **정해진 시각에 신청이 열리고, 여러 사람이 같은 정원을 두고 경쟁하는 상황**을 그대로 만들어서 몇 번이든 연습할 수 있게 한다.

### 핵심 기능

| # | 기능 | 사용자 입력 | 결과 |
|---|---|---|---|
| 1 | 시간표 추천 | 목표 학점, 공강 요일, 오전 수업 제외 여부 | 시간이 겹치지 않는 과목 조합을 최대 3개 추천 |
| 2 | 장바구니 | 추천 결과나 과목 목록에서 [담기] | 담은 과목을 시간표로 표시. 시간 겹침, 중복, 21학점 초과는 거부 |
| 3 | 수강신청 | 신청이 열린 뒤 [신청] | 신청 성공 시 잔여 정원 감소. 오픈 전 신청과 정원 마감은 거부 |
| 4 | 신청 현황·내역 | 없음 (자동 갱신) | 과목별 신청 인원과 남은 자리를 1초마다 표시, 내가 신청한 과목은 시간표로 표시 |
| 5 | 관리자 | 관리자 키, 오픈까지 대기 시간 | 신청 오픈·마감·초기화, 초당 신청 요청 수와 워커별 처리 건수 확인 |

로그인 없이 닉네임만 입력하면 이용할 수 있다.

### 이용이 몰리는 기능

수강신청이 이 서비스에서 이용이 몰리는 기능이다.

```
오픈 전    모든 사용자가 수강신청 화면에서 카운트다운을 보며 대기
오픈       접속자 전원이 장바구니 과목을 동시에 신청
           → 신청 요청이 한꺼번에 서버로 들어옴
           → 정원 5명 과목에 수십 명이 몰려도 5명만 성공, 나머지는 "정원 마감"
```

## 2. AWS 구성도

### 사용자 요청 경로

```
                      AWS EC2 (보안 그룹: 80번 전체 공개, 22번 내 IP만 허용)
               ┌────────────────────────────────────────────────────────────┐
               │  Docker Compose                                            │
               │                                                            │
 브라우저 ──────┼──→ Nginx :80 ──── /api/ ────→ Flask :5000 (gunicorn)       │
 http://IP/    │    화면 파일 제공               ├ 워커 1 ─┐                  │
               │    (html, js)                 ├ 워커 2 ─┼─→ Redis :6379    │
               │                               └ 워커 3 ─┘   잔여 정원       │
               │                               courses.json  장바구니        │
               │                               (과목 정보)    신청 내역       │
               │                                             요청 통계       │
               └────────────────────────────────────────────────────────────┘
```

| 요청 | 경로 |
|---|---|
| 화면 열기 | 브라우저 → EC2 80번 → Nginx가 html 파일 응답 |
| 시간표 추천 | 브라우저 → Nginx → Flask 워커가 `courses.json`으로 조합 계산 |
| 수강신청 | 브라우저 → Nginx → Flask 워커 → Redis에서 정원 차감 → 결과 응답 |

### 사용한 AWS 서비스

| 서비스 | 역할 | 선택 이유 |
|---|---|---|
| **EC2** (Ubuntu 24.04) | Docker Compose로 Nginx, Flask, Redis 컨테이너를 실행하는 가상 서버 | 로컬에서 확인한 Compose 구성을 수정 없이 그대로 실행할 수 있음 |
| **보안 그룹** | 80번(HTTP)만 전체 공개, 22번(SSH)은 내 IP만 허용 | Flask(5000)와 Redis(6379)를 외부에 열지 않기 위함 |

### 컨테이너 구성

| 컨테이너 | 역할 | 외부 공개 |
|---|---|---|
| Nginx | 화면 파일 제공, `/api/` 요청을 Flask로 전달 | 80번 |
| Flask (gunicorn 워커 3개) | 시간표 추천, 장바구니, 수강신청 처리 | 공개 안 함 |
| Redis | 잔여 정원, 장바구니, 신청 내역, 요청 통계 저장 | 공개 안 함 |

### 몰리는 요청을 처리하는 방법

gunicorn 워커는 서로 다른 프로세스라 메모리를 공유하지 않는다.
정원을 파이썬 변수에 두면 워커마다 따로 세어서, 정원 30명인 과목에 최대 90명이 성공할 수 있다.

그래서 정원을 **Redis 한 곳**에 두고, 신청할 때 `DECR` 명령으로 "1 빼기"와 "결과 확인"을 한 번에 처리한다.

```
워커 1: DECR → 결과 0   → 0 이상이므로 신청 성공
워커 2: DECR → 결과 -1  → 0보다 작으므로 INCR로 되돌리고 "정원 마감"
```

Redis는 명령을 한 번에 하나씩 처리하므로, 요청이 동시에 들어와도 정원보다 많이 신청되지 않는다.

### ELB · Auto Scaling 검토

**적용하지 않았다.**

| 항목 | 내용 |
|---|---|
| 부하 특성 | 평소에는 접속이 거의 없고, 신청 오픈 직후 몇 초 동안만 요청이 몰림 |
| 적용하지 않은 이유 | 서버를 2대 이상으로 늘리려면 Redis를 EC2 밖(ElastiCache 등)으로 분리해야 하고, ALB 비용도 계속 발생함. 연습용 서비스 규모에서는 EC2 1대의 워커 3개로 처리할 수 있다고 판단함 |
| 확장을 고려한 설계 | 정원과 신청 내역을 서버 메모리가 아닌 Redis에 두었으므로, 서버를 늘려도 Redis만 공유하면 코드를 바꾸지 않아도 됨 |
| 적용한다면 | 수강신청은 몰리는 시각을 미리 알 수 있으므로, 오픈 시각 전에 서버 수를 늘려두는 예약 확장이 적합함 |

## 3. 실행·배포 방법

### 준비 사항

- 로컬: Docker Desktop, Git
- AWS: EC2 인스턴스 1대 (Ubuntu 24.04), 키 페어(.pem)

### 로컬 실행

```bash
git clone https://github.com/sua050806/course-practice.git
cd course-practice
docker compose config          # 설정 검사
docker compose up -d --build   # 빌드 후 실행
docker compose ps              # 컨테이너 3개 실행 확인
curl http://localhost/api/health
```

- 접속 주소: http://localhost/
- `{"redis": true, "status": "ok", ...}`가 나오면 정상

### AWS 배포 절차

**1. EC2 인스턴스 생성**

| 항목 | 설정 |
|---|---|
| AMI | Ubuntu Server 24.04 LTS |
| 키 페어 | 새로 생성 (.pem) |
| 보안 그룹 | SSH 22: 내 IP / HTTP 80: 0.0.0.0/0 |

**2. SSH 접속**

```bash
ssh -i course-practice.pem ubuntu@3.106.254.102
```

**3. Docker, Git 설치**

```bash
sudo apt update
sudo apt install -y docker.io docker-compose-v2 git
sudo usermod -aG docker ubuntu
exit        # 그룹 설정을 적용하려면 다시 접속
```

**4. 코드 받아서 실행**

```bash
git clone https://github.com/sua050806/course-practice.git
cd course-practice
echo "ADMIN_KEY=원하는키" > .env    # 관리자 키 설정 (없으면 기본값 사용)
docker compose up -d --build
curl http://localhost/api/health
```

**5. 코드 수정 후 다시 배포**

```bash
cd ~/course-practice
git pull
docker compose up -d --build
```

**6. 인스턴스를 중지했다가 다시 켠 경우**

```bash
cd ~/course-practice
docker compose up -d
```

인스턴스를 중지했다가 켜면 퍼블릭 IP가 바뀌므로 접속 주소도 새 IP로 바뀐다.

### 포트와 접속 주소

| 대상 | 포트 | 공개 범위 |
|---|---|---|
| Nginx | 80 | 전체 공개 |
| Flask | 5000 | 컨테이너 내부만 |
| Redis | 6379 | 컨테이너 내부만 |
| SSH | 22 | 내 IP만 |

| 화면 | 주소 |
|---|---|
| 첫 화면 (닉네임 입력) | http://3.106.254.102/ |
| 시간표 추천 | http://3.106.254.102/recommend.html |
| 장바구니 | http://3.106.254.102/cart.html |
| 수강신청 | http://3.106.254.102/enroll.html |
| 관리자 | http://3.106.254.102/admin.html |
| 서버 상태 확인 | http://3.106.254.102/api/health |

### 사용 순서

1. 관리자 화면에서 관리자 키 인증 → [초기화]
2. 첫 화면에서 닉네임 입력 → 시간표 추천 → 장바구니에 담기
3. 수강신청 화면에서 대기
4. 관리자 화면에서 대기 시간을 정하고 [오픈]
5. 카운트다운이 끝나면 수강신청 화면에서 [신청]
6. 과목별 신청 현황과 신청 내역 확인
